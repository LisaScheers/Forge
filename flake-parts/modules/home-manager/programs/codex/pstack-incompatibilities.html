How to review

One skill

Run git diff -- flake-parts/modules/home-manager/programs/codex/pstack/skills/<skill>. The staged file is upstream; the working file is the proposed Codex version.

Selective staging

Use git add -p for individual hunks or git add <path> after accepting a complete skill. New policy files remain untracked until you stage them.

Return to upstream

To discard one proposed adaptation while keeping the staged baseline, restore only the working tree copy for that path from the index.

What changed across the set

AreaWorking-tree adaptation
Paths and invocationRepository skills use .agents/skills and explicit references use $skill-name. Cursor rule, transcript, and plugin paths were removed from active entrypoints.
Parallel workParallel skills use Codex collaboration agents, inherited models, exclusive file ownership, and evidence contracts. Ordinary skills delegate only when the user explicitly asks for parallel work.
Questions and authorityQuestions remain read-only. External messages, tickets, PRs, pushes, merges, deployments, production changes, and destructive cleanup keep their normal authorization boundaries.
PR workflowOpening and monitoring route to $file-pr and $babysit-pr. No skill treats PR creation or merging as an automatic tail step.
ModelsHard-coded Cursor model slugs are gone. Optional role choices are advisory, repository-local, validated against the current collaboration tool, and inherit the parent by default.
History and connectorsRecall and why use scoped Codex history, Git, and currently available connected sources. Missing connectors are reported as coverage gaps.
Personal fitComment preservation, YAGNI, focused tests, source-of-truth fixes, safe Nix boundaries, and minimal delegation now match Forge's instructions.
